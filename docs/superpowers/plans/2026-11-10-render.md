# Render deployment implementation plan

**Goal:** Run the existing browser UI and Python API on Render without a continuously running personal computer.

**Architecture:** One free Docker web service serves the built React files and `/api` on the same HTTPS origin. MongoDB Atlas stores accounts/metadata; managed files and settings are ephemeral and the UI warns users. Existing desktop startup and local bearer-token protection stay intact.

**Scope:** `backend/app/main.py`, new `backend/app/web.py`, shared encryption in `backend/app/db.py`, dependency declarations, Dockerfile/context, Render Blueprint, focused tests, and deployment instructions. No React rewrite. Existing Linux-incompatible DWG converter and local GPU model are not bundled; their existing unavailable states remain explicit.

**Decisions:** User selected Render and explicitly chose the free trial version. External provisioning awaits a connected Render account. A new `bim_insight_render_demo` database avoids modifying the desktop database. Do not copy local credentials, personal files, model weights, or working data into the image. Uploads are capped at 20 MiB and existing worker RSS controls at 256 MiB; large IFC files are outside this demo's scope. Free Render blocks the existing Gmail SMTP transport.

## Review focus

Public bootstrap takeover; account/project authorization bypass; unknown origins/hosts; wrong encryption key after restart; accidental inclusion of personal data in the image; container memory limits; free-tier file loss and blocked Gmail SMTP.
